## Consequences for the design

1. **Streaming in the dext is feasible on paper.** Isochronous OUT and IN, the
   feedback pipe (which is also isochronous), class requests for the UAC2 clock
   and sample rate, and alt-setting selection are all in the SDK. This removes
   the main Phase 6 "SDK blocked" risk, pending Phase 6 hardware results.
2. **Named devices.** Five output devices and three input devices are created
   with `AddObject`. All of them share one clock domain ID, so CoreAudio treats
   them as synchronous. The dext packs and unpacks the multichannel USB stream
   to and from the per-device stream buffers.
3. **Open question for Phase 2/6: what one frame entry covers.** The SDK
   exposes only `IOUSBIsochronousFrame`. If the GoXLR is a high-speed device
   with `bInterval = 1` (125 µs), we must determine whether one entry
   represents a 1 ms frame or a 125 µs microframe on Apple Silicon. Classify
   this as **unknown** until a Phase 2 descriptor dump and a Phase 6 test
   resolve it. Phase 6 adds a test that fails until it is resolved.
4. The kernel-only `IOUSBHostIsochronousTransaction` API isn't available, so
   implementation guides written for kexts don't carry over one to one.
